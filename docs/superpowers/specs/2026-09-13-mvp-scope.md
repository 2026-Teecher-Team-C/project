## 핵심 한 줄

**에이전트가 다운로드를 가로채서 붙잡고 있다가, 서버에 물어보고, 안전하면 흘려보내고 위험하면
막는다.** 이 흐름 하나를 끝까지 동작시키는 것이 MVP의 전부다.

## 포함 기능

| #   | 기능                 | 설명                                                         |
| --- | ------------------ | ---------------------------------------------------------- |
| A   | 다운로드 트래픽 감지        | Content-Disposition/MIME/size로 다운로드 여부 판별, 다운로드가 아니면 즉시 통과 |
| B   | 응답 보류              | 다운로드 응답 헤더가 브라우저로 전송되기 전에 붙잡아둠                             |
| C   | 스트리밍 SHA-256 + 스풀링 | 파일을 디스크에 스풀하면서 동시에 해시 계산 (단일 패스)                           |
| D   | 에이전트 → 서버 통신       | 해시(및 캐시 미스 시 파일)를 서버로 전송하고 verdict 수신                      |
| E   | 서버 판정              | 해시 대조(블랙리스트) + 기본 YARA 매칭으로 안전/악성 판정                       |
| F   | 릴리스/차단 처리          | 판정에 따라 응답을 그대로 흘려보내거나 403으로 차단                             |
| G   | 최소 판정 이력 저장        | 판정 결과를 최소 형태(SQLite/인메모리)로 기록                              |

## 제외 기능 (MVP 범위 밖)

- 블룸 필터 / Redis 캐싱 — 캐시 미스 취급하고 매번 서버에 조회
- 서킷 브레이커 + 로컬 SQLite 캐시 폴백 — 2026-09-15 결정: 초기 단계에서는 미구성. 서버 장애 시
  재시도/서킷브레이커/캐시 조회 없이 정책값(fail-open/fail-close)만 즉시 적용
- PE 헤더 엔트로피 분석 — YARA 매칭까지만
- 외부 위협 인텔리전스(VirusTotal/NVD·CVE) 연동 — 2026-09-15 회의로 MVP 범위뿐 아니라 전체 범위에서 제외 확정
- 관리 콘솔(React) — 필요 시 로그 출력으로 대체
- Prometheus/Grafana 모니터링, Slack 알림
- 격리 파일 오탐 복원, RDS PostgreSQL 정식 스키마
- Docker/CI 배포 파이프라인 — 로컬 실행으로 시연

## 데모 시나리오 (목표)

1. 안전한 파일 다운로드 → 정상적으로 저장됨
2. EICAR 테스트 파일/악성 샘플 다운로드 → 차단됨 (403 또는 차단 알림)
